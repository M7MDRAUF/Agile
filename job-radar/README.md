# Job Radar — رادار الوظائف

نظام يبحث كل ساعتين عن وظائف **Junior / New Grad / Entry Level** في مجال هندسة البرمجيات وتطوير الـ Full-Stack، ويرسل لك إشعارًا على جوالك بالوظائف الجديدة فقط.

نظام مستقل داخل المجلد `job-radar/` ولا يرتبط بتطبيق AgileForge.

## كيف يعمل

1. **الجلب**: يقرأ الوظائف من مصادر عامة بدون مفاتيح API (انظر الجدول أدناه).
2. **الفلترة بالتاريخ**: أي وظيفة نُشرت قبل `startDate` (اليوم 3 نوفمبر 2026، بتوقيت لوس أنجلوس) تُتجاهل نهائيًا. وتُتجاهل أيضًا الوظائف الأقدم من `maxAgeHours` (72 ساعة افتراضيًا)، والوظائف التي ليس لها تاريخ نشر، لأنه لا يمكن إثبات أنها جديدة.
3. **المطابقة**: يفهم أسماء الوظائف المختلفة (انظر "الأسماء المدعومة").
4. **منع التكرار**: كل وظيفة تصلك مرة واحدة فقط، حتى لو ظهرت في أكثر من مصدر.
5. **الإشعار**: رسالة واحدة (أو أكثر إذا كانت الوظائف كثيرة) كل دورة، والنقر على الإشعار يفتح أول وظيفة.

إذا لم توجد وظائف جديدة في الدورة يصلك إشعار صامت قصير ("لا جديد في هذه الدورة") ليؤكد أن النظام يعمل. لإيقافه اجعل `notifyWhenEmpty` تساوي `false` في `config.json`.

## الأسماء المدعومة

يقبل العنوان إذا كان **دورًا برمجيًا** (Software Engineer / Developer / SWE / SDE / Full Stack / Web / Frontend / Backend / Mobile / لغة أو إطار مثل Java أو React أو Node ...) **مع** أحد مؤشرات المستوى المبتدئ:

| النوع         | أمثلة                                                                                                                                                                                                  |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| خريج جديد     | New Grad، NewGrad، New Graduate، Recent Graduate، Fresh Graduate، Graduate، Grad، University Grad، Campus Hire، Class of 2027، 2027 New Grad، Early Career، Early Talent، Fresher، Trainee، Apprentice |
| مستوى مبتدئ   | Entry Level / Entry-Level، Junior / Jr.، Associate Software Engineer                                                                                                                                   |
| ترقيم المستوى | Software Engineer I / 1، SDE I / 1، SWE I، Level 1                                                                                                                                                     |

ويرفض: Senior، Sr، Staff، Principal، Lead، Manager، Director، Architect، المستويات II وما فوق، التدريب (Intern / Co-op) ما لم تفعّله، والأدوار غير البرمجية (Sales، Support، Hardware، Account ...).

العنوان العادي مثل `Software Engineer` بدون مؤشر مستوى يُقبل **فقط** إذا أثبت وصف الوظيفة أنها للمبتدئين (entry-level، new grad، 0-1 years ...). وإذا طلب الوصف أكثر من `maxYearsExperience` سنة (افتراضيًا 2) تُرفض الوظيفة.

## المصادر

| المصدر                      | ملاحظات                                                                            |
| --------------------------- | ---------------------------------------------------------------------------------- |
| Greenhouse / Lever / Ashby  | صفحات توظيف شركات محددة (قائمة في `config.json`، وتستطيع إضافة شركاتك)             |
| Simplify New-Grad-Positions | قائمة مجتمعية لوظائف الخريجين الجدد                                                |
| Arbeitnow                   | وظائف أوروبا وعن بُعد                                                              |
| Remote OK                   | وظائف عن بُعد (الإشعارات تذكر المصدر وتربط بصفحته كما تشترط شروطهم)                |
| Remotive                    | وظائف عن بُعد. موقعهم يطلب حدًا أقصى 4 طلبات يوميًا، لذلك يُجلب مرة كل 6 ساعات فقط |

**حدود يجب أن تعرفها**: لا يوجد مصدر عام مجاني لـ LinkedIn أو Indeed أو Glassdoor (واجهاتهم مغلقة أو تمنع الجلب الآلي)، لذلك لا يغطيهم النظام. التغطية الحالية قوية للشركات التقنية التي تستخدم Greenhouse/Lever/Ashby ولقوائم الخريجين الجدد. أضف شركاتك المفضلة في `sources.greenhouse` / `lever` / `ashby` (الاسم هو الجزء الأخير من رابط صفحة التوظيف، مثل `boards.greenhouse.io/stripe` ← `stripe`).

## التشغيل التلقائي كل ساعتين (GitHub Actions)

الملف `.github/workflows/job-radar.yml` يعمل بجدولة `17 */2 * * *` (كل ساعتين، بالتوقيت UTC). لا تحتاج لجهاز يعمل طوال الوقت.

### 1) إعداد الإشعارات (اختر واحدة على الأقل)

**الخيار الأسهل: ntfy**

1. ثبّت تطبيق **ntfy** على جوالك (iOS / Android).
2. اشترك في Topic باسم طويل وعشوائي، مثل `jobs-x7k2m9q4p8w3`. أي شخص يعرف اسم الـ Topic يستطيع قراءة إشعاراتك، فلا تستخدم اسمًا بسيطًا.
3. أضف السر `NTFY_TOPIC` بهذا الاسم.

**أو Telegram**

1. أنشئ بوتًا عبر `@BotFather` واحصل على التوكن.
2. أرسل أي رسالة للبوت، ثم اعرف رقم محادثتك (مثلًا عبر `https://api.telegram.org/bot<TOKEN>/getUpdates`).
3. أضف السرّين `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID`.

الأسرار تُضاف من: GitHub ← Settings ← Secrets and variables ← Actions ← New repository secret.

### 2) التفعيل

1. ادمج هذا الفرع في الفرع الرئيسي (`main`)، لأن GitHub لا يشغّل الجدولة إلا من الفرع الافتراضي.
2. من تبويب **Actions** شغّل **Job Radar** يدويًا مرة واحدة (`Run workflow`). يمكنك تفعيل `dry_run` لرؤية النتائج بدون إرسال.
3. بعدها يعمل تلقائيًا كل ساعتين.

يحفظ النظام ما أرسله سابقًا في فرع منفصل اسمه `job-radar-state` (ملف `state.json` فقط)، فلا يلوّث تاريخ الكود الرئيسي.

ملاحظات عن GitHub Actions:

- الجدولة قد تتأخر بضع دقائق عند ازدحام GitHub، وهذا طبيعي.
- GitHub يوقف الـ workflows المجدولة تلقائيًا في المستودعات العامة بعد 60 يومًا بلا نشاط. إذا توقفت الإشعارات، شغّل الـ workflow يدويًا مرة لإعادة تفعيله.

## التشغيل على جهازك أو سيرفرك

```bash
cd job-radar
npm ci

export NTFY_TOPIC=jobs-x7k2m9q4p8w3   # أو TELEGRAM_BOT_TOKEN و TELEGRAM_CHAT_ID

npm run test-notify   # يرسل رسالة تجريبية للتأكد من الإشعارات
npm run dry-run       # يعرض الوظائف المطابقة بدون إرسال أو حفظ
npm run once          # دورة واحدة كاملة
npm run watch         # يعمل باستمرار ويكرر كل intervalMinutes (120 دقيقة)
```

الحالة تُحفظ في `job-radar/.state/state.json`. لتشغيل `watch` في الخلفية على سيرفر استخدم `systemd` أو `pm2` أو `tmux`. أو استخدم cron:

```cron
0 */2 * * * cd /path/to/job-radar && NTFY_TOPIC=... npm run once >> radar.log 2>&1
```

## الإعدادات (`config.json`)

| المفتاح                                 | الوصف                                                                                                         |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `startDate`                             | تاريخ البداية بصيغة ISO مع المنطقة الزمنية. الافتراضي `2026-11-03T00:00:00-08:00` (بداية اليوم في لوس أنجلوس) |
| `maxAgeHours`                           | أقصى عمر للوظيفة بالساعات (72)                                                                                |
| `maxYearsExperience`                    | أقصى سنوات خبرة مسموحة في الوصف (2)                                                                           |
| `locations`                             | قائمة مواقع، مثل `["riyadh", "saudi", "canada", "united states"]`. فارغة = كل الأماكن                         |
| `remoteAlwaysMatches`                   | عند `true` تمر وظائف الـ Remote حتى مع تحديد `locations`                                                      |
| `includeInternships`                    | تضمين التدريب (Intern / Co-op). افتراضيًا `false`                                                             |
| `allowUnleveledTitles`                  | قبول `Software Engineer` العادي بدون أي دليل على المستوى. يزيد النتائج والضوضاء بشكل كبير                     |
| `extraRoleKeywords` / `excludeKeywords` | كلمات إضافية للأدوار المقبولة، أو كلمات تُستبعد من العنوان                                                    |
| `notifyWhenEmpty`                       | إشعار صامت عند عدم وجود جديد                                                                                  |
| `maxJobsPerRun`                         | أقصى عدد وظائف في الدورة. الزائد يصل في الدورة التالية                                                        |
| `timezone`                              | المنطقة الزمنية للوقت المعروض في الإشعار                                                                      |
| `sources`                               | تفعيل/تعطيل المصادر وقوائم الشركات                                                                            |

متغير البيئة `JOB_RADAR_START_DATE` يتجاوز `startDate` دون تعديل الملف.

**مهم**: أول مرة يعمل فيها النظام يعتمد على `startDate` فقط ليتجاهل القديم، فلا يوجد "إغراق" بوظائف قديمة. وإذا غيّرت `startDate` إلى تاريخ أقدم ستتلقى وظائف أقدم لم تُرسل بعد.

## ما الذي يحدث عند الأعطال

- فشل مصدر واحد: تستمر الدورة بباقي المصادر، ويظهر اسم المصدر الفاشل في أسفل الإشعار.
- فشل كل المصادر، أو فشل كل قنوات الإشعار: تنتهي الدورة بخطأ (يظهر أحمر في GitHub Actions) ولا تُسجَّل الوظائف كمُرسلة، فتصلك في الدورة التالية.
- الوظيفة التي تظهر في أكثر من مصدر (نفس الشركة والعنوان، أو نفس رقم الوظيفة في Greenhouse/Lever/Ashby) تُرسل مرة واحدة فقط. وبالمقابل، وظيفتان بنفس الشركة والعنوان في مدينتين تُعاملان كوظيفة واحدة.

cd job-radar
